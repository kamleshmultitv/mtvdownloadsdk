# Codex Task: Fix MTV Downloader DRM Offline Downloads

Use this document as the full task brief for Codex when working inside the MTV downloader SDK project.

## Goal

Fix DRM protected content download in the MTV downloader SDK so that AOL Widevine DASH content can be downloaded and played offline.

The SDK must not only download the MPD and media segments. It must also acquire a Widevine offline license, persist the returned `keySetId`, and attach that `keySetId` during offline playback.

The AOL Android app already has a working ExoPlayer DRM offline flow documented here:

Use that document as the behavior reference.

## Current Known Facts

Current AOL production package/application id:

```gradle
applicationId "com.sspt.aol"
```

There is also a commented id in AOL `app/build.gradle`:

```gradle
// applicationId "com.aol.multitv"
```

Package name is not directly sent in the AOL DRM license URL, but it can still matter if the DRM/license backend whitelists app package name, signing certificate, app id, device id behavior, or token audience.

Do not assume package name is irrelevant. Confirm it.

## Main Root Causes To Check

DRM downloads usually fail for one of these reasons:

1. SDK downloads encrypted media but never requests an offline Widevine license.
2. SDK requests a streaming license instead of an offline license.
3. SDK does not store the returned `keySetId`.
4. SDK stores `keySetId` but does not attach it during offline playback.
5. License URL payload is wrong or missing `download = "1"`.
6. `k_id` does not match the MPD DRM data.
7. The MPD does not contain Widevine PSSH/DRM init data.
8. The license backend rejects the request because of package name, signing certificate, auth token, device id, or whitelist rules.
9. SDK download cache and playback cache are different.
10. App tries to reuse a `keySetId` generated by a different package/app install.

## Package Name and Signing Requirement

Check this early.

Package name itself is not a Widevine client-side API requirement, but the backend can enforce it. Also, Widevine offline licenses are local to the device/app DRM storage and should not be treated as portable between apps.

Codex must verify:

- MTV SDK app `applicationId`.
- AOL app `applicationId`.
- Signing certificate/SHA-1/SHA-256 used for debug and release.
- Whether the license backend/EZDRM panel whitelists package name, signing cert, or app id.
- Whether AOL auth tokens are valid for the MTV package/app.
- Whether the same license URL works from the AOL app but fails from MTV app on the same device.

If MTV app uses a different package or signing key, ask backend/DRM team to whitelist it or provide a valid license config for that package.

Do not try to copy a Widevine `keySetId` from AOL app storage to MTV SDK app storage. It will not be reliable.

## License URL Contract

Build the license URL exactly like AOL:

Base:

```text
BuildConfig.DRM_LICENSE_URL
```

Production AOL value:

```text
https://widevine-dash.ezdrm.com/widevine-php/widevine-foreignkey.php?pX=63CF74&
```

Query params:

```text
user_id=<device guid>
type=widevine
authorization=<aol auth token>
payload=<Base64 NO_WRAP JSON>
```

Payload JSON:

```json
{
  "content_id": "<content id>",
  "k_id": "<widevine key id>",
  "user_id": "<logged in AOL user id>",
  "package_id": "<active subscription/package id>",
  "licence_duration": "<seconds>",
  "security_level": "0",
  "rental_duration": "0",
  "content_type": "1",
  "download": "1",
  "can_renew": true
}
```

Rules:

- Use `licence_duration`, not `license_duration`.
- Use `k_id`, not `kid`.
- Use `download = "1"` for offline download.
- Use Base64 without line wraps.
- Redact `authorization` and `payload` in logs.

Device GUID reference:

```kotlin
val androidId = Settings.Secure.getString(context.contentResolver, Settings.Secure.ANDROID_ID)
val serialId = Build.SERIAL
val guid = UUID.nameUUIDFromBytes("$androidId$serialId".toByteArray())
val userIdForLicenseUrl = Base64.encodeToString(guid.toString().toByteArray(), Base64.NO_WRAP)
```

If MTV SDK already has a different device id strategy, confirm backend accepts it.

## Required SDK Behavior

### 1. Detect DRM Content Correctly

Do not rely only on URL ending with `.mpd`.

Use:

- API DRM metadata if available.
- Stream MIME type.
- ExoPlayer/Media3 content type inference.
- Manifest inspection for DRM init data.

Current AOL flow supports Widevine DASH MPD. If MTV SDK receives DRM HLS, either implement that explicitly or return a clear unsupported error.

### 2. Build DRM Media Item

For ExoPlayer 2.x:

```kotlin
val mediaItem = MediaItem.Builder()
    .setUri(mpdUrl)
    .setMimeType(MimeTypes.APPLICATION_MPD)
    .setDrmConfiguration(
        MediaItem.DrmConfiguration.Builder(C.WIDEVINE_UUID)
            .setLicenseUri(licenseUrl)
            .build()
    )
    .build()
```

For Media3, use equivalent `androidx.media3.common.MediaItem` and `androidx.media3.common.C`.

### 3. Prepare Manifest

Use `DownloadHelper` to prepare the manifest and track groups.

ExoPlayer 2.x example:

```kotlin
val helper = DownloadHelper.forMediaItem(
    context,
    mediaItem,
    DefaultRenderersFactory(context),
    httpDataSourceFactory
)

helper.prepare(callback)
```

### 4. Find DRM Init Data

Find the first format that contains DRM data:

```kotlin
fun findFirstFormatWithDrmInitData(helper: DownloadHelper): Format? {
    for (periodIndex in 0 until helper.periodCount) {
        val mappedTrackInfo = helper.getMappedTrackInfo(periodIndex)
        for (rendererIndex in 0 until mappedTrackInfo.rendererCount) {
            val groups = mappedTrackInfo.getTrackGroups(rendererIndex)
            for (groupIndex in 0 until groups.length) {
                val group = groups[groupIndex]
                for (formatIndex in 0 until group.length) {
                    val format = group.getFormat(formatIndex)
                    if (format.drmInitData != null) {
                        return format
                    }
                }
            }
        }
    }
    return null
}
```

If this returns null for a DRM item, fail with:

```text
DRM_INIT_DATA_MISSING
```

Also log:

- content id
- URL type
- whether URL is MPD/M3U8
- whether DRM metadata exists from API
- sanitized license query keys

### 5. Acquire Offline Widevine License

This is mandatory.

ExoPlayer 2.x:

```kotlin
val offlineLicenseHelper = OfflineLicenseHelper.newWidevineInstance(
    licenseUrl,
    false,
    httpDataSourceFactory,
    emptyMap(),
    DrmSessionEventListener.EventDispatcher()
)

val keySetId: ByteArray = offlineLicenseHelper.downloadLicense(drmFormat)
offlineLicenseHelper.release()
```

The returned `keySetId` must be non-null and non-empty.

If this fails, expose the real error stage:

```text
OFFLINE_LICENSE_REQUEST_FAILED
```

Capture sanitized exception details:

- exception class
- cause class
- DRM error code if available
- license URL host/path/query keys
- HTTP response code if exposed

Do not log the full license URL.

### 6. Build Download Request With keySetId

ExoPlayer 2.x:

```kotlin
val downloadRequest = helper
    .getDownloadRequest(contentId, estimatedBytes)
    .copyWithKeySetId(keySetId)
```

If the SDK has its own request model, it must store the equivalent `keySetId`.

The media segments are encrypted. A download request without `keySetId` is not enough for offline playback.

### 7. Persist keySetId

Persist `keySetId` in SDK/app download metadata.

Recommended storage format:

```kotlin
val keySetIdBase64 = Base64.encodeToString(keySetId, Base64.NO_WRAP)
```

Save at minimum:

- content id
- original stream URL
- MIME/content type
- DRM scheme: Widevine
- license URL metadata or rebuild inputs
- `k_id`
- `keySetIdBase64`
- expiry time
- selected stream keys/tracks
- download cache id/request id

Important:

- Store initial `keySetId` immediately after license acquisition.
- Update it again after license renewal.
- Do not store only in memory.

### 8. Download Media Segments

Start the SDK's download process only after `keySetId` has been acquired.

If using ExoPlayer `DownloadService`:

```kotlin
DownloadService.sendAddDownload(
    context,
    MyDownloadService::class.java,
    downloadRequest,
    true
)
```

If using custom SDK download manager, ensure it stores:

- encrypted segment cache
- manifest
- stream keys/tracks
- download request id
- associated `keySetId`

### 9. Offline Playback Must Attach keySetId

Offline playback must not use only the cached MPD/segments.

Build a DRM media item using saved `keySetId`:

```kotlin
val keySetIdBytes = Base64.decode(savedKeySetIdBase64, Base64.DEFAULT)

val offlineItem = MediaItem.Builder()
    .setUri(savedMpdUrl)
    .setMimeType(MimeTypes.APPLICATION_MPD)
    .setDrmConfiguration(
        MediaItem.DrmConfiguration.Builder(C.WIDEVINE_UUID)
            .setKeySetId(keySetIdBytes)
            .build()
    )
    .build()
```

Player must use the same cache/index where the download was stored.

### 10. License Renewal

When local expiry is reached:

1. Rebuild fresh license URL with new `licence_duration`.
2. Prepare the same MPD.
3. Find DRM format.
4. Call `OfflineLicenseHelper.downloadLicense(format)`.
5. Save the new `keySetIdBase64`.
6. Update expiry date.
7. Playback must use the new `keySetId`.

### 11. Delete Download

Delete should:

- remove cached media
- remove download metadata
- release offline license if SDK supports it

ExoPlayer helper has:

```kotlin
offlineLicenseHelper.releaseLicense(keySetId)
```

Implement if possible.

## Acceptance Criteria

Codex must finish with these checks passing:

1. A DRM DASH MPD item downloads successfully in MTV SDK.
2. Offline license request returns non-empty `keySetId`.
3. `keySetId` is persisted as Base64.
4. Download can resume after app process restart.
5. Offline playback works with internet disabled.
6. Offline playback still works after app restart.
7. License renewal updates stored `keySetId`.
8. Deleting download removes cached media and metadata.
9. Non-DRM downloads still work.
10. Failure logs identify exact failing stage.

Manual test:

```text
1. Login with valid AOL user.
2. Open a known DRM DASH content item.
3. Build license URL.
4. Start download.
5. Confirm offline license success and keySetId saved.
6. Wait for download complete.
7. Kill app.
8. Disable internet.
9. Reopen app.
10. Play downloaded item.
11. Confirm playback starts without license URL/network.
```

## Minimal Fix Strategy

If the SDK currently downloads files but fails DRM:

1. Add license URL builder compatible with AOL.
2. Add manifest prepare step.
3. Add Widevine offline license acquisition.
4. Store `keySetId`.
5. Attach `keySetId` during offline playback.
6. Add package/signing whitelist verification with backend.

Do these before changing segment download logic.

## Do Not Do

- Do not copy `keySetId` between different apps/packages.
- Do not assume cached encrypted segments can play without offline license.
- Do not log raw tokens or DRM payload.
- Do not ignore package/signing backend whitelist.
- Do not treat `.m3u8` DRM as supported unless explicitly implemented.
- Do not start segment download before offline license succeeds for DRM items.

## Expected Final Implementation Shape

The MTV SDK should expose a clear interface similar to:

```kotlin
data class DrmDownloadInput(
    val contentId: String,
    val mpdUrl: String,
    val licenseUrl: String,
    val kId: String,
    val title: String,
    val durationMs: Long
)

data class DrmDownloadRecord(
    val contentId: String,
    val mpdUrl: String,
    val keySetIdBase64: String,
    val mimeType: String,
    val expiryTimeMillis: Long
)

interface DrmDownloader {
    suspend fun startDownload(input: DrmDownloadInput): DrmDownloadRecord
    suspend fun renewLicense(record: DrmDownloadRecord, freshLicenseUrl: String): DrmDownloadRecord
    suspend fun removeDownload(record: DrmDownloadRecord)
}
```

The important part is not the interface name. The important part is that `startDownload` returns/saves a valid offline Widevine `keySetId`.
